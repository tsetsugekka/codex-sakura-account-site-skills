# 新しいページを既存サイトに組み込む

入力はページの目的、所属プロジェクト、公開範囲とデータ源。既存の AGENTS.md、仕様、共通部品、生成・公開手順を読む。ユーザーに「この旧ページを土台に」と指定させず、実際の共通実装から組み立てる。

## ページの契約

所属モジュールの文書に、公開 URL・ソース・配布先の対応、公開/認証境界、検索対象の本文、初回のデータ範囲、更新元と失敗時表示を簡潔に記録する。既存の文書構成を使い、単純なページに不要なサービスや定時処理を追加しない。

- 固定説明は初期 HTML の通常の本文にする。記事・分析・一覧は検索してほしい実内容、図表・計算ツールは用途と必要な概要を選び、大きな履歴や操作は JS 側に残す。JSON を原本として使ってよい。
- `noscript` だけを検索本文にしない。初期本文とアプリが同じ場所を管理する場合、JS 起動だけで本文が消えないよう所有範囲を決める。具体的な生成・引き継ぎ方式はプロジェクトで検証し、全ページに SSR を強制しない。
- Sidebar、Header、Footer、言語、字体、認証は共通実装を再利用する。コピー元の業務や隠れた旧メニューを引き継がない。共有実行ファイル方式ならその読み込み契約に従い、ページ本体に別実装を埋め込まない。
- 画面上のメニュー表示とサーバーのアクセス権を分ける。共有部品の変更は実際の依存先を確認し、不要な全ページ再生成を避ける。

## 必要な技能だけ使う

| 条件 | 技能と受け取る結果 |
| --- | --- |
| 検索や共有の対象 | `public-page-seo-assist`：初期本文、メタ情報、URL と検証結果 |
| 初回/再取得の費用を確認 | `web-performance-slimming`：実転送量、要求数、必要な圧縮・読込設計 |
| データ・ログ・バックアップが増える | `data-growth-guard`：原本/派生物の区別、保存と整理の境界 |
| 定時生成や外部収集がある | `cron-crawler-safety`：時刻表、リクエスト制限、失敗と公開の扱い |
| 静的配布・サーバー生成物がある | `static-deploy-refresh-check`：配布順序、保護対象、更新確認 |

同梱または導入済みの対象 SKILL.md を必要時だけ読む。未導入なら取得が必要なものを示すか、プロジェクトの同等手順を使う。全技能の実行を義務化せず、技能を読んだだけで検証済みとしない。

SSH、メール、認証、秘密設定は既存基盤を使う。新設が必要で依頼範囲に含まれるときだけ対応する `sakura-*-setup` / `sakura-api-secrets-deploy` を使う。

## 完了の確認

初期 HTML、JS 起動後、初回データ取得失敗、直接 URL を開く場合を確認する。デスクトップ/モバイルの共通部品と言語、必要なデータ読込、公開後の生成物を検証し、実装・公開・検索収録の状態を分けて報告する。

既存ページや既存自動生成器が新しい記事を出すだけでは本技能による移行を始めない。個別技能は既存ページの改善にも単独で使える。これは既存経験を整理した作成手順であり、未検証の新ページを動作保証する雛形ではない。
